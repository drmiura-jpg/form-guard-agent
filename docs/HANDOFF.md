## 1. プロダクト概要（誰の・どんな課題を・どう変えるか）

### 冒頭の一文（公式指定フォーマット・148字）
> **このプロジェクトは、大学・自治体・医療現場などの申請業務で「指定様式の罫線や計算式が崩れると差し戻されるためAIを使えない」と困っている担当者・研究者の課題を、元の白紙様式は一切触らず指定欄だけをピンポイントで書き換え、欄外の不変を自動検査して人が最終承認する形に変える書類記入エージェントです。**

### 誰の・どんな課題か（原体験）
- 開発者自身が倫理審査や研究計画書などの書類作成で何度も「書式・罫線・文言の崩れ」による差し戻しに遭い、生成AIを試しても枠線や結合セルが崩れてしまい「もうAIを使うのはやめようか」とまで思った実体験から出発しています。
- 日本の大学・研究機関・自治体・施設管理の現場では、Word（`.docx`）・Excel（`.xlsx`）・固定レイアウト PDF（`.pdf`）の公式様式に対し**「元の書式・罫線・結合セル・計算式・定型文を1箇所も変えないこと」**が鉄則です。文書全体を生成AIで作り直す方式では枠線や数式が壊れ、どこが崩れたか探すだけで手作業以上の負担になっていました。

### どう変えるか（Form-Guard Agent の3つの革新）
1. **指定欄だけの外科的ピンポイント置換＋7区分・21項目の構造検査＆視覚比較（`VIS-01`）**:
   - Word / Excel の対象テキストノードのバイト範囲（固定PDFは末尾への増分追記オーバーレイ）だけを書き換え、スタイル・罫線・フォント等の無変更パーツ（例：`form1` の18パーツ中17パーツ）は再圧縮すら行わず生バイト複製します。
   - 記入直後に **7区分・21項目の決定論的構造検査** と **内蔵の視覚配置比較（`VIS-01`：付属デモで欄外のずれ `0 px`）** を自動実行します。
2. **目印（`{{マーカー}}`）のない白紙様式からの4段階・空欄自動発見**:
   - タグが埋め込まれていない生の白紙様式（`form4`〜`form10`）から、AIと構造解析で **「申請者記入欄（緑）」** と **「事務局専用欄（受付番号・受付日・審査欄など：赤ロック）」** を自動仕分けし、事務局欄や Excel の `SUM`/`COUNTIF` 数式セルへの誤記入をロックします。
3. **原文引用スパン照合（推測ゼロ設計）＋Claude 3モデル使い分け＋人間承認ゲート**:
   - すべての記入値に元メモの**原文引用（行番号・黄色ハイライト）**を紐づけ、メモに書かれていない事実（法人番号など）は当てずっぽうで埋めず **`needs_human_input`（人の入力待ち）** に残します。
   - 欄の難易度に応じて **Haiku 4.5**（日付・和暦・番号・空欄分類）、**Sonnet 5**（氏名・金額・自由記述の原文引用抽出）、**Opus 5.5 Adaptive Thinking**（200字以内の要約短縮と上限違反等の再提案）の3モデルを自動ルーティングします。
   - MCP にはあえて「承認ツール」を置かず、**人間が Web 画面で全項目をチェックして承認ボタンを押すまでダウンロードをサーバー側でロック** します。

## 2. 技術構成と起動手順（必要なツール・環境変数の「名前」のみ）

### 技術スタック
- **言語・ランタイム**: Python 3.10+（推奨 3.11 / 3.12）
- **Web フレームワーク**: FastAPI + Uvicorn（`form_guard/server.py`）
- **文書解析・ピンポイント置換エンジン**: `lxml` / `zipfile`（OOXML 生バイト保持置換）、`pypdf` / `reportlab` / `pymupdf`（固定PDF 増分オーバーレイ＆画素比較）、`Pillow`（内蔵レイアウト描画比較 `VIS-01`）
- **AI モデル連携**: Anthropic Python SDK（`anthropic`）による3階層ルーティング（`form_guard/mapper.py`）※APIキー未設定時は自動的に決定論的ルールエンジン `DemoEngine` で動作
- **Claude Code 拡張機能（リポジトリ同梱）**:
  - **2段フック**: `.claude/settings.json` ＋ `scripts/hook_guard.py`（`PreToolUse` で白紙様式の改変や秘密情報混入を `exit 2`＋`deny` で遮断、`PostToolUse` で構文・import・JSON を自動検査）
  - **4サブエージェント（`Edit`/`Write` ツール非付与）**: `.claude/agents/`（`memo-extractor`, `field-mapper`, `structure-auditor`, `form-auditor`）
  - **6 Skills**: `.claude/skills/`（`form-scan`, `surgical-fill`, `structural-audit`, `form-fill-verify`, `visual-diff-audit`, `portal-form-fill`）
  - **5ツール MCP サーバー（追加SDK不要・標準入出力 JSON-RPC 2.0）**: `.mcp.json` ＋ `form_guard/mcp_server.py`（`form_guard_list_demos`, `form_guard_scan`, `form_guard_discover_blank_cells`, `form_guard_fill`, `form_guard_verify`）

### 環境変数の「名前」一覧（値は記載しません。必要時のみ `.env` またはシェルに設定）
- **`FORM_GUARD_API_KEY`**（または **`ANTHROPIC_API_KEY`**）:
  - `--mode live` や Web 画面で実際の Claude API を呼び出す場合のみ使用（**未設定でもオフラインデモモードで全機能が動きます**）。
- **`FORM_GUARD_FORCE_DEMO`**:
  - `1` に設定すると、PC内に API キーが存在していても通信を一切行わず、高速・無料のオフラインデモモードに固定します（収録時のトラブル防止におすすめ）。
- **`FORM_GUARD_ACCESS_KEY`** / **`FORM_GUARD_ALLOWED_HOSTS`**:
  - `scripts/share_tunnel.ps1` で外部トンネルを開くときだけスクリプトが自動設定する合言葉・ホスト制限用変数（通常は設定不要）。
- **`FORM_GUARD_HOOK_PYTHON`**:
  - Claude Code フックが使用する Python パスを上書きする場合のみ使用（未設定時は `.venv` を自動優先）。

### 新宿 PC での30秒起動手順（コピペ用）

  - 審査員が `git clone` して `python -m form_guard.cli --serve`（または `--all-demos --mode demo`）を実行するだけで、**有料アカウントも API キーもログインも一切なしで**、全10種の架空様式デモ・21項目検査・視覚比較・人間承認ゲートを追試できます。
